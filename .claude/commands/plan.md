## 기획자 역할 활성화

`AGENTS.md`의 기획자(Planner) 역할 규칙을 따른다.

### 사전 확인: 명령 수신 확인 (Command Recognition Gate)

**절차 시작 전 최우선으로 수행한다.** AGENTS.md의 "명령 수신 확인 프로토콜" 형식으로 사용자에게 확인을 받는다:

```
📌 명령 수신 확인

[명령]: /plan (실행 계획 작성)
[원본 지시]: {$ARGUMENTS 원문}

[작업 요약]:
1. {기획할 기능/작업 1}
2. ...

[실행 범위]:
- 대상: {영향받는 기능/영역}
- 브랜치: {현재 브랜치}
- 배포: 없음 (계획 작성만)

[주의사항]: {있으면 기재, 없으면 "없음"}

이 이해가 맞으면 "컨펌"으로 승인해주세요.
```

사용자 컨펌 후 아래 절차로 진행한다.

### 절차

1. 사용자에게 작업 범위를 확인 (불명확하면 질문)
2. `docs/exec-plans/templates/sprint-contract.md` 템플릿을 복사
3. `docs/exec-plans/active/{작업명}.md` 생성 (영어 kebab-case 파일명)
4. 아래 항목을 구체적으로 작성:
   - **Phase A — 제품 검증** (기술 명세 전 필수):
     - A1. 사용자 여정 맵 (진입점 → 화면별 인터랙션 → 탈출점)
     - A2. 기능 완성도 감사 (12가지 상태 체크 — 빈 칸 금지)
     - A3. 연결점 분석 (네비게이션, 대시보드, API 의존성 등)
     - A4. 상용 준비도 (데모 가능? 플레이스홀더 없는가? 등)
     - A5. 서비스 품질 (온보딩, 에러, 빈 상태, 모바일 등)
   - **Phase B — 기술 명세**:
     - 범위 (포함/제외 항목)
     - 수용 기준 (검증 가능한 기준 + 제품 품질 시나리오 P1~P3)
     - 영향 파일 목록 (실제 파일 경로)
     - 구현 명세 (파일별 현재→목표 상태, 실제 코드 기반)
     - 연쇄 반영 체크리스트
     - 롤백 계획
     - 작업 단계 체크리스트
5. (선택) **외부 LLM 크로스리뷰** — 다른 모델/리뷰어에게 플랜을 독립 검토시키고 blocker/improvement를 플랜에 병합. 템플릿: `docs/exec-plans/templates/external-review-prompt.md`
6. 사용자에게 실행 계획 파일 경로 안내 + 승인 요청

### 완료 조건

- 실행 계획 파일이 `docs/exec-plans/active/`에 존재
- 수용 기준이 구체적으로 정의됨 (빌드 성공, 테스트 통과 등)
- 영향받는 파일 목록이 식별됨
- 사용자가 승인함
