## 구현자 역할 활성화

`AGENTS.md`의 구현자(Implementer) 역할 규칙을 따른다.

---

### Phase 0: 명령 수신 확인 (Command Recognition Gate)

**최우선으로 수행한다.** AGENTS.md의 "명령 수신 확인 프로토콜" 형식으로 확인:

```
📌 명령 수신 확인

[명령]: /implement (구현)
[원본 지시]: {$ARGUMENTS 원문}

[작업 요약]:
1. {구체적 작업 항목 1}
2. ...

[실행 범위]:
- 대상: {영향받는 파일/기능}
- 브랜치: {현재 브랜치}
- 배포: 없음 (구현만)

[주의사항]: {있으면 기재, 없으면 "없음"}

이 이해가 맞으면 "컨펌"으로 승인해주세요.
```

사용자 컨펌 후 Phase 1로 진행. `$ARGUMENTS` 원문을 `ORIGINAL_INSTRUCTION`으로 저장한다.

---

### Phase 1: 사전 확인 (Pre-coding)

1. `docs/exec-plans/active/`에 승인된 실행 계획이 있는지 확인 (없으면 `/plan` 먼저 안내 후 중단)
2. 실행 계획 파일을 읽는다
3. **의도 섹션** 확인 — 비즈니스 목적, 성공의 모습, 판단 기준
4. **구현 명세 섹션** 확인 — 각 파일의 변경 의도, 현재→목표 상태, 제약 조건
5. 변경 대상 파일을 **모두 읽는다**
6. 각 변경 대상의 호출 사이트를 grep으로 추적한다
7. **사전 확인 체크리스트**의 모든 항목을 확인한다

---

### Phase 2: 구현 확인 (Implementation Confirmation)

사용자에게 변경 계획을 보고한다:

```
📋 구현 확인 요청
계획: {계획명}

[파일 1] {파일 경로} ({신규/수정})
- 변경 의도: {1문장}
- 핵심 변경점:
  - {함수명}({파라미터}): {현재 동작} → {목표 동작}
  - {주의사항 / 제약 조건}

[파일 2] ...

승인하시면 구현을 시작합니다.
```

**사용자 승인 후에만** 코드 작성을 시작한다.

---

### Phase 3: 단계별 구현

실행 계획의 작업 단계 그룹을 순서대로 진행한다.

- 각 단계 완료 시 실행 계획 파일의 체크박스를 체크한다
- **단계 그룹 완료마다** (최소 3단계마다) `{{BUILD_CMD}}`를 실행하여 타입 에러를 조기 발견한다
- 빌드 실패 시 즉시 수정 후 재빌드 — 다음 단계로 진행하지 않는다
- 연쇄 반영 체크리스트(API↔UI, DB↔서비스, i18n, 타입/Props)를 매 그룹 확인한다
- **범위 잠금 검사**: 단계 그룹 완료마다 `git diff --name-only HEAD`로 수정 파일 확인. 계획에 없는 파일이 수정됐으면 **즉시 중단**하고 사용자에게 보고. 롤백 후 재작업.

---

### Phase 4: 구현 완료

1. `{{BUILD_CMD}}` 최종 확인
2. 실행 계획 파일의 상태를 "진행중" → "구현완료"로 변경

---

### Phase 4.5: 원본 지시 검증 (Original Instruction Verification)

결과 보고 전에 **반드시** 수행한다. Phase 0의 `ORIGINAL_INSTRUCTION` 기준으로 출력:

```
📋 원본 지시 검증

[원본 지시]: {ORIGINAL_INSTRUCTION}

| # | 요구사항 | 구현 여부 | 근거 |
|---|---------|----------|------|
| 1 | {요구사항} | ✅/❌ | {파일/빌드 결과} |

[미충족 항목]: {없음 / 목록}
```

- 미충족 항목이 있으면 Phase 3으로 돌아가서 추가 구현 후 재검증
- 모든 항목 충족 시 → 결과 보고
