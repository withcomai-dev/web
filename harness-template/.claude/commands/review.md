## 검토자 역할 활성화

`AGENTS.md`의 검토자(Reviewer) 역할 규칙을 따른다.

### 사전 확인: 명령 수신 확인 (Command Recognition Gate)

**절차 시작 전 최우선으로 수행한다.** AGENTS.md의 "명령 수신 확인 프로토콜" 형식으로 확인:

```
📌 명령 수신 확인

[명령]: /review (품질 검토)
[원본 지시]: {$ARGUMENTS 원문 또는 "최근 변경 파일 검토"}

[작업 요약]:
1. {검토 대상 파일/기능 1}
2. ...

[실행 범위]:
- 대상: {변경된 파일 목록}
- 브랜치: {현재 브랜치}
- 배포: 없음 (검토만)

[주의사항]: {있으면 기재, 없으면 "없음"}

이 이해가 맞으면 "컨펌"으로 승인해주세요.
```

사용자 컨펌 후 아래 절차로 진행한다.

### 절차

`docs/QUALITY_SCORE.md`의 체크리스트를 항목별로 검증한다:

**A. 코드 품질 (필수)**
- 타입 에러: `{{BUILD_CMD}}` 결과 확인
- 느슨한 타입(`any` 등): 변경 파일 grep
- 린트: `{{LINT_CMD}}` 결과 확인
- 비즈니스 로직 캡슐화: 라우트 핸들러에 직접 로직 있는지 확인
- 주석: 새 클래스/함수에 문서화 주석 있는지 확인

**B. 설계 품질**
- 단일 책임 원칙 준수 여부
- 기존 패턴 일관성
- 연쇄 반영 완료 여부 (i18n, docs 동기화)

**C. 보안 (필수)**
- 시크릿/API Key 평문 노출 없는지 변경 파일 확인
- 외부 입력에 스키마 검증(Zod 등) 적용 여부
- 에러 응답 내부 정보 미노출 여부
- 런타임 호환 (금지 API 미사용)

**D. 테스트 가능성**
- try-catch 존재 여부
- 실행 로그 기록 여부

**E. 문서 동기화**
- progress.md 업데이트 여부
- 테스트 레퍼런스 업데이트 여부 (UI 변경 시)
- i18n 반영 여부

**F. 서비스 품질 / G. 디자인 품질** — QUALITY_SCORE.md §F·§G 참조

### 보고 형식

```
🔍 품질 검토 완료
- 등급: 통과 / 조건부 통과 / 미달
- A 코드 품질: N/5 ✅/❌
- B 설계 품질: N/4 ✅/⚠️
- C 보안: N/4 ✅/❌
- D 테스트: N/2 ✅/⚠️
- E 문서: N/4 ✅/⚠️
- F 서비스 품질 / G 디자인 품질: 요약
- 미달 항목: (없음 / 있으면 수정 목록)
```

미달 시 수정 항목 목록을 제공하고 재평가를 요청한다.
