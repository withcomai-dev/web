# 구현자 (Implementer) 역할

> AGENTS.md §역할 정의에서 분리된 상세 행동 규칙. AGENTS.md 코어와 함께 읽어야 한다.
> Skill `/implement` 활성화 시 이 파일을 추가 로드한다.
> **영구 등재 규칙(★★★)은 위반 시 즉시 BUG 등록 — 가장 중요**.

---

## 활성화 조건

- 트리거 키워드: `개발해` / `구현해` / 승인된 실행 계획 존재
- 대응 명령: `/implement`
- 소규모 변경(1~3 파일): 실행 계획 없이 바로 진입 가능

---

## 필수 행동

- 코드 작성 전 변경 대상 파일을 **모두 읽고** 호출 사이트를 grep으로 추적한다
- 실행 계획의 **사전 확인 체크리스트** 완료 후 **구현 확인 보고**를 사용자에게 제출 → 승인 후 코딩 시작 (**단, `/auto` 자율 모드에서는 보고 없이 즉시 코딩**)
- 실행 계획의 작업 단계 체크리스트 순서대로 작업
- CLAUDE.md §코딩 규칙의 연쇄 반영 준수 (API↔UI, DB↔서비스, i18n, 타입/Props)
- 단계 그룹마다 (최소 3단계마다) `{{BUILD_CMD}}`로 중간 검증
- **UI 코드 작성 시 "세계 최고 디자이너 마인드셋" 적용** — 여백·계층·워딩·일관성을 매 파일마다 자문
- **구현 완료 후 완결성 자가 검증** — 진입→실행→결과확인→복귀 경로가 모두 존재하는지 점검
- 완료 후 `docs/QUALITY_SCORE.md` 자가 평가 (G 디자인 품질 포함)

---

## 영구 등재 규칙 (★★★ 위반 시 즉시 BUG)

> 이 규칙들은 실제 프로젝트에서 같은 실수가 2~4회 반복된 뒤 영구 등재된 것이다.
> 프로젝트에 해당 없는 항목(i18n·디자인 토큰 등)은 삭제한다.

### ★ 네비게이션·라우트 구조 변경 시 도달 경로 검증 필수

- `{{NAV_FILE}}`(네비게이션 정의) · 라우팅 파일(page/redirect) 수정 시 점검
- 변경 영향 받는 모든 페이지에 대해 "이 페이지로 어떻게 도달?" 답할 수 있어야 함
- 답이 "URL 직접 입력만"이면 fallback 진입점(Hub Nav · 인라인 링크) 추가 필수
- 메뉴 children 제거·통합 시 → 하위 페이지 진입점 자동으로 사라지지 않는지 사전 점검
- mockup의 핵심 변경 포인트를 체크리스트로 분해 → 각 항목 ✅ 표시 후 보고 (부분 구현 후 "다 했다" 보고 금지)

### ★★★ 글로벌 디자인 변경 후 페이지별 시각 점검 필수

- 글로벌 디자인 컴포넌트(globals.css · Card · Button 등) 수정 시 → **영향 받는 모든 페이지 스크린샷으로 직접 확인 필수** (브라우저 MCP `take_screenshot`)
- 페이지마다 자체 카드·헤더·spacing 사용하는 곳은 **개별 폴리시** 필요 (전역 토큰만 바꾸면 통일 안 됨)
- 사용자에게 "디자인 통일 완료" 보고 전 → 스크린샷 N장 + 페이지 목록 첨부
- 페이지마다 디자인이 다르면 ❌ — 사용자는 "전체 통일"을 기본 기대

### ★★★ 디자인 토큰만 사용 (타이포그래피 등)

- 허용 토큰: `{{TYPO_TOKENS}}`
- **금지**: 임의 픽셀값(`text-[Npx]`)·스케일 클래스 직접 사용
- 위계 매핑: 페이지 제목=최상위 / 섹션 / 카드 타이틀 / 본문 / 라벨·보조 순으로 토큰 적용
- 정의 위치: `{{TYPO_TOKEN_DEF}}`
- (디자인 토큰 시스템이 없으면 이 규칙 삭제)

### ★★★ i18n 누수 차단 — 사용자 노출 문자열은 모두 `t()`

- 새 컴포넌트나 기존 UI 수정 시 사용자 노출 모든 문자열은 `t('section.key')` 패턴 필수
- 의도적 분기는 `lang === 'en' ? 'X' : '한글'` 명시 (인라인 분기도 OK)
- {{I18N_FILES}} **양쪽 동시** 추가 — 한쪽만 추가 금지
- **변경 직전 자동 가드**: `{{I18N_CHECK_CMD}}` 실행 — 하드코딩 누수 검출
- **다국어 영향 컴포넌트 변경 후**: `?lang=en` URL 시각 검증 필수
- (단일 언어 프로젝트면 이 규칙 삭제)

## 금지 행동

- 실행 계획 범위 밖 파일 변경
- 품질 체크 없이 완료 선언
- 테스트 없이 배포 진행
- **구현 확인 보고 없이 코드 작성 시작** (단, `/auto` 자율 모드 제외)
- **변경 대상 파일을 읽지 않고 변경 시작**
- **디자인 마인드셋 없이 UI 코드 작성** — "동작하면 됨" 마인드로 워딩·여백·계층을 방치
- **완결성 자가 검증 없이 구현 완료 선언** — 진입 경로·결과 확인·에러 안내가 빠진 반쪽짜리 결과물
