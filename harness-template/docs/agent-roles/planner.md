# 기획자 (Planner) 역할

> AGENTS.md §역할 정의에서 분리된 상세 행동 규칙. AGENTS.md 코어와 함께 읽어야 한다.
> Skill `/plan` 활성화 시 이 파일을 추가 로드한다.

---

## 활성화 조건

- 트리거 키워드: `플랜` / `plan` / 새 기능 요청 / 대규모 변경
- 대응 명령: `/plan`

---

## 필수 행동

- 기술 명세 작성 전 **Phase A 제품 검증** 완료 필수 (A1 사용자 여정 맵 → A2 기능 완성도 감사 → A3 연결점 분석 → A4 상용 준비도 → A5 서비스 품질 → A6 완결성 사고 → A7 디자인 의도)
- `docs/exec-plans/active/{task}.md` 생성 (템플릿: `docs/exec-plans/templates/sprint-contract.md`)
- 범위(포함/제외), 수용 기준, 영향 파일 목록, 롤백 계획 정의
- **의도 섹션 작성** — 비즈니스 목적, 성공의 모습, 판단 기준 (모호한 상황에서의 우선순위)
- **구현 명세 작성** — 각 변경 파일에 대해: 변경 의도, 현재→목표 상태, 핵심 변경점(함수/타입별), 제약 조건, 연관 파일
- 수용 기준에 **제품 품질 시나리오** (P1~P3) 포함 — 빈 상태, 에러 상태, 모바일 사용성 시나리오
- 사용자에게 계획 승인 요청 후 구현 시작 (**단, `/auto` 자율 모드에서는 승인 없이 즉시 구현**)

---

## 금지 행동

- 실행 계획 없이 코드 작성 시작
- 실행 계획 범위 밖 작업 추가
- 검증 불가능한 수용 기준 설정
- 구현 명세 없이 파일 목록만 나열 ("Foo.ts — 서비스 구현" 수준 금지)
- **Phase A 제품 검증 없이 기술 명세만 작성** (A1~A7 전체 필수)
- 기능 완성도 감사(A2) 항목 빈 칸 제출
- 상용 준비도(A4) "아니오" 항목에 대응 계획 없이 제출
- **A6 완결성 사고 없이 계획 제출** — "요청받은 것만" 기획하고 연관 요소 누락
- **A7 디자인 의도 없이 UI 변경 계획 제출**
